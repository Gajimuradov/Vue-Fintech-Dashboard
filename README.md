# Vue Fintech Dashboard

Небольшой, но аккуратно собранный dashboard для финтех-операций. Проект сделан как портфолио-кейс для frontend internship: без лишнего визуального шума, с понятной таблицей, фильтрами, отдельной страницей операции, mock API и тестами для ключевых сценариев.

В интерфейсе можно быстро посмотреть пополнения, выводы, платежи и переводы, найти нужную операцию по клиенту или id, отфильтровать список по статусу и типу, а затем открыть карточку с деталями и историей изменения статуса. Над таблицей есть короткая аналитика: дневная динамика операций, распределение по статусам и типам, а суммы показываются отдельно по валютам.

## Стек

- Vue 3 и Composition API
- TypeScript
- Vite
- Pinia
- Vue Router
- MSW
- Vitest
- Playwright
- Scoped CSS

## Что внутри

- Dashboard-страница со списком операций.
- Таблица с ключевыми полями: `id`, `amount`, `currency`, `status`, `type`, `createdAt`, `userName`.
- Поиск по имени клиента и id операции.
- Фильтры по статусу и типу операции.
- Сортировка по дате и сумме.
- Дневной график операций: видно, как менялся поток по дням.
- Аналитика по статусам и типам: количество, доля и суммы внутри каждой группы.
- Суммы разделены по валютам, без смешивания USD, EUR и GBP в один общий показатель.
- Детальная страница операции с полной информацией и историей статусов.
- Mock API через MSW: приложение делает обычный `fetch('/api/transactions')`, а service worker возвращает тестовые данные.
- Искусственная задержка ответа и сценарий ошибки для проверки loading/error состояний.
- Pinia store с loading, error, empty, no-results состояниями и computed selectors.
- Отдельная бизнес-логика для фильтрации, сортировки, валютных итогов и аналитики.
- Unit-тесты для selectors, фильтров, сортировки, дневной динамики, валютных итогов и store.
- E2E-тест Playwright для пути: открыть dashboard, проверить аналитику, отфильтровать список, перейти в детали.

## Как устроен mock API

Данные лежат в `src/data/transactions.ts`, а обработчики MSW описаны в `src/mocks/handlers.ts`. В dev-режиме браузерный worker стартует перед монтированием Vue-приложения. В unit-тестах используется `msw/node`, поэтому store тестируется через тот же API-клиент, что и приложение.

Кнопка «Показать ошибку» отправляет запрос с параметром `scenario=error`, и MSW возвращает HTTP 503. Так можно проверить не только happy path, но и состояние ошибки без настоящего backend.

## Что показывает проект

Проект демонстрирует близкий к реальной разработке frontend-подход: типизированные данные, разделение UI и логики, управление состоянием через Pinia, роутинг, API-слой через `fetch`, реалистичный mocking через MSW, обработку разных состояний интерфейса и тестирование пользовательского сценария.

Для стажировки в финтехе это хороший пример того, что кандидат понимает не только компоненты, но и продуктовую механику: операции должны быть легко читаемыми, фильтры предсказуемыми, валюты нельзя складывать в один условный показатель, а ошибка или пустой результат не должны ломать пользовательский опыт.
